## PartnerCenterBridge v0.9.2

The Windows Local Workbench now opens as a desktop application. Double-click
`PartnerCenterBridge.exe` to launch a branded WPF window containing the existing React app in
WebView2. The API, SQLite store, account system, tenant connections, and operation code run in the
same process. The API listens only on localhost, picks an available port, and stops when the window
closes. A second launch focuses the existing window for that Windows user.

Microsoft Edge WebView2 Runtime is required. The app displays an installation hint if it is
missing. WebView2 uses a profile under the workbench data directory, so its local app session is
preserved across restarts when the previous loopback port remains available. If another process
occupies it, the app picks a new port and may ask you to sign in locally again. Microsoft tenant
connections remain protected in the shared store. External links, including Microsoft sign-in,
open in the system browser.

The existing browser and tray experience remains available with `--browser`. `--no-browser` starts
the local API from a terminal; `doctor`, `bootstrap-sam`, `--help`, and `--version` remain available.
The desktop and CLI modes share one data directory and the same local security policy.

Microsoft connections now leads with **Add tenant with Microsoft** in Settings and Tenants.
The optional Partner Center/GDAP configuration and manual token recovery are collapsed advanced
controls. Release builds include the publisher's public client ID so technicians do not register
an application per customer tenant. The publisher registration must be supplied before release.

The signed Windows zip contains the desktop executable. The container API and web images remain
available for server deployments. No new database migration is required for this release.

To build locally, run `./scripts/publish-local.ps1`. The Windows CI and release pipelines test
both the CLI/loopback API and desktop startup before packaging.
