## PartnerCenterBridge v0.9.1

This release makes the Local Workbench's Exchange Online setup actionable. When PowerShell 7 or
the ExchangeOnlineManagement module is missing, an instance Administrator can install it from the
Home setup checklist or Settings > Workbench health. The same screen keeps the manual command
available for managed machines.

### Guided dependency setup

- Installing PowerShell 7 uses WinGet on Windows. Installing ExchangeOnlineManagement runs
  `Install-Module` for the current user through the PowerShell 7 executable the workbench found.
  Each action requires confirmation and runs a fixed, allowlisted command; the API does not accept
  shell text or executable paths from the browser.
- Choosing **Not now** records a visible blocked check across browser and workbench restarts.
  A successful install clears that decision, refreshes the Exchange dependency probe, and makes
  the new executable available to Exchange operations without restarting the workbench.
- The Home and Settings checks refresh in the background every minute, so a dependency installed
  outside the app also appears without pressing Re-run checks.
- If `Exchange:PwshPath` names a missing custom location, diagnostics direct you to correct that
  setting instead of offering an install that cannot satisfy it.

Exchange Online still needs an app registration and app-only certificate. The installer changes
only the local PowerShell dependencies; it does not configure Microsoft credentials or make
tenant changes.

### Workbench branding and Windows tray

- The app, executable, Windows tray and documentation website use the bridge logo from the
  approved navy-and-azure branding direction. The website has a new responsive opening layout.
- Explorer launches detach the console after the tray is ready. Double-click the tray icon to
  reopen the workbench; its menu opens logs or exits. Terminal launches retain the terminal.
  `--no-browser` and `--Hosting:Tray=false` retain console operation.

### Direct Microsoft tenant connections

- In the loopback-only Local Workbench, **Add tenant with Microsoft** opens Microsoft sign-in in
  the system browser, then discovers the organization and registers it. Repeat for each admin tenant.
- Configure `MicrosoftSignIn:ClientId` once using a multitenant desktop app registration with a
  localhost redirect and delegated Graph permissions. See the Local Workbench documentation.
- Each local operator/tenant pair has an encrypted MSAL cache. Tokens renew silently; interaction
  requirements surface as **Reconnect** for the saved username and tenant. Existing workbench
  tenant permissions remain enforced, and admin identities are not shared between operators.
- This connects Graph. Partner Center retains SAM/GDAP; Exchange retains its certificate setup.
  Shared-server sign-in and unattended use of these direct admin identities are outside this scope.

### Downloads and containers

The Windows x64 zip contains the signed `PartnerCenterBridge.exe`, `LICENSE`, and
`README-FIRST.txt`. Download the matching `.sha256` file from this release and compare it with
the zip before extracting. The API and web container images are published at
`ghcr.io/spillers-technology/partnercenterbridge-api:0.9.1` and
`ghcr.io/spillers-technology/partnercenterbridge-web:0.9.1` (also `:latest`).

### Known limits

- Microsoft sign-in needs a configured multitenant app registration and customer admin consent.
  Automated checks cover authorization, cache isolation, reconnect state and UI behavior; live
  Microsoft consent, MFA and Conditional Access still need verification with the release app ID.
- The automatic PowerShell install requires WinGet on Windows; on machines without it, use the
  displayed manual command or your organization's software deployment tool.
- WinGet and PowerShell module installation require access to their configured package sources.
  The installation subprocess has not been exercised against a live package source in CI; CI
  covers the API authorization, persisted decisions, executable-path refresh, and UI flow.

### Checksum verification

```powershell
$zip = "PartnerCenterBridge-v0.9.1-win-x64.zip"
$expected = (Get-Content "$zip.sha256" -Raw).Trim().Split()[0]
(Get-FileHash $zip -Algorithm SHA256).Hash.ToLower() -eq $expected
```

`True` means the zip matches the published checksum. After extraction,
`Get-AuthenticodeSignature .\PartnerCenterBridge.exe` should report `Valid`.
