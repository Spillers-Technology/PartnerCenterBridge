## PartnerCenterBridge v0.10.0

Tenant audits: read-only health checks for a Microsoft 365 tenant. Open a tenant and choose the
new **Audits** tab (or **Run a health check** on its Overview), pick the full health check or
individual categories, set the inactivity thresholds, and run. PCB reads the tenant's
configuration and changes nothing.

Twenty-five checks ship in five categories:

- **Identity hygiene**: stale enabled accounts, inactive admin accounts, privileged role review,
  MFA registration coverage, admin authentication strength, guest account review, stale guests.
- **Licensing**: dormant licensed users, disabled accounts with licenses, licensed shared
  mailboxes, subscription seat utilization.
- **Exchange / Mail**: external mailbox forwarding, mailbox delegation review, shared mailbox
  sign-in, mailbox archive state.
- **Endpoint / Intune**: stale devices, non-compliant devices, compliance policy coverage, device
  encryption, duplicate device records.
- **Tenant security**: sign-in protection baseline (security defaults or Conditional Access),
  Conditional Access exclusions, user consent and directory defaults, app consent review, and
  configuration drift since the last config snapshot.

Each finding is graded Pass, Info, Unknown, Warn or Fail. It shows the evidence behind it, one
sentence of business impact and a recommendation. A check PCB cannot run in a tenant (a missing
permission or admin role, no Entra ID P1, no Intune, Exchange not set up) is shown as
**Unavailable** with the reason and what is missing, instead of passing silently or failing the
whole audit.

**Dormant licensed users** defaults to 90 days (30, 60, 180 or a custom 7-730). It keeps "last
successful sign-in" apart from "last sign-in attempt", and lists accounts with recent attempts but
no recorded success as Unknown rather than guessing. Accounts with no recorded sign-in, new
accounts, and shared or resource mailboxes are listed separately. Each dormant user links to
**Plan offboarding**. The check reports what Microsoft Entra's sign-in data proves, not whether
someone used Microsoft 365.

Every run is saved and can be reopened. Each run exports as:

- **CSV**: one normalized row per affected item; Excel-safe, with spreadsheet formula injection
  neutralized.
- **JSON**: the full report.
- **Markdown**: ticket and customer notes.

`GET /api/tenant-audits/estate` summarizes the latest audit of every tenant you can see.

Viewer on a tenant can run and read its audits. Direct tenant sign-in needs no new consent: the
bundled registration already requests the Graph permissions the checks use, and a Global Reader
sign-in covers them. Partner Center/GDAP setups can add the optional `AuditLog.Read.All`,
`Directory.Read.All` and `DeviceManagementManagedDevices.Read.All` permissions and a Global Reader
GDAP role. Exchange checks use the existing app-only Exchange connection with `Get-` cmdlets only.

This is an assessment aid, not a compliance certification. See the
[Tenant audits guide](https://spillerstech.us/PartnerCenterBridge/tenant-audits.html) for the
check catalog, permissions, sign-in semantics, export formats and limitations.

This release adds a database migration (`TenantAudits`, one new table). It is applied
automatically at startup for both the Local Workbench (SQLite) and server (PostgreSQL)
deployments. The web image's nginx configuration allows audit runs up to five minutes.
