Get started

Partner Center Bridge ships as one signed Windows program. Download it, run it, create the administrator account (or skip it on an already-secured machine), and connect it to your partner tenant. There is no server, database or identity provider to set up first. If your team wants one shared instance instead, see Run as a server.

Partner Center Bridge v0.9.2 for Windows

PartnerCenterBridge-v0.9.2-win-x64.zip · about 107 MB · signed by Joseph Spillers · SHA-256 checksum published next to it

Download from GitHub Releases

Requirements

  • 64-bit Windows (x64). The release is self-contained, so you do not need to install .NET. Only a win-x64 build is published. There is no macOS or Linux executable.
  • Microsoft Edge WebView2 Runtime. The desktop window uses it to show the app. If missing, the app shows an installation hint. A current browser remains useful for Microsoft account sign-in and the optional browser/tray mode.
  • To work in customer tenants: a CSP partner tenant, a multi-tenant Entra app registration, and a GDAP relationship with each customer. See Connect Microsoft.
  • For mailbox features only: PowerShell 7, the ExchangeOnlineManagement module and an app-only certificate. Everything else works without them. See Exchange Online.

1. Download and verify

From the latest release, download PartnerCenterBridge-v0.9.2-win-x64.zip and the .sha256 file published next to it. Before you unzip, check that the hash matches. In PowerShell, from the download folder: 

$zip = "PartnerCenterBridge-v0.9.2-win-x64.zip"
$expected = (Get-Content "$zip.sha256" -Raw).Trim().Split()[0]
(Get-FileHash $zip -Algorithm SHA256).Hash -eq $expected   # True means the zip is intact

The executable is Authenticode-signed by Joseph Spillers. After unzipping you can confirm the signature in the file's Properties › Digital Signatures tab, or run: 

Get-AuthenticodeSignature .\PartnerCenterBridge.exe | Format-List Status, SignerCertificate

If you would rather build it yourself, ./scripts/publish-local.ps1 produces the same single-file exe from source. See Local Workbench: building it.

2. Run it

Unzip to a folder of your choice and start the program:

.\PartnerCenterBridge.exe

On first launch it creates its data folder, sets up its SQLite database, and opens the workbench in its desktop window. Close the window to stop the local API. Launching the exe a second time brings the existing window forward. Use --browser for the classic browser/tray mode.

Good to knowDetail
Where your data lives%LOCALAPPDATA%\PartnerCenterBridge: the database, encryption keys, logs and uploaded app packages. Change it with --data-dir.
Who can reach itOnly this machine. It listens on the loopback address unless you pass --listen.
Another portDesktop mode picks an available loopback port automatically. .\PartnerCenterBridge.exe --port 5090 starts the CLI host on a chosen port.
Check dependencies.\PartnerCenterBridge.exe doctor prints every check with its fix and exits (exit code 1 if anything is an error).
All options.\PartnerCenterBridge.exe --help, or see Local Workbench: running it.

3. First launch: create the administrator

A new install has no accounts, so the first screen asks how you want to use it:

  • Create an administrator account (recommended). The first account you register becomes the instance Administrator. After that you sign in with a passkey (once you register one under your account's Security settings) or your password, and you can add TOTP two-factor authentication. Anyone else who registers later starts with no access until you share tenants with them. See Authentication.
  • Skip — use without an account on this computer. An explicit choice for a machine that is already secured: screen lock, disk encryption, and no shared Windows account. The program opens your browser with a single-use setup link. After choosing this option, it uses a single-use sign-in link that expires after two minutes; run the exe again for a fresh one. Opening a bookmark later just tells you to start it from PartnerCenterBridge.exe again. Registering a password, a passkey, or TOTP is blocked until then; MCP access tokens still work. Add a password anytime from Settings > Account & security > Protect with an account.
The no-account owner gets instance Administrator and nothing else -- like any account, it only gains access to a tenant once it adds or syncs that tenant. The no-account option exists only in the Windows program: it is never available in server or Docker mode, and first run refuses to offer it when the program is started with a non-loopback --listen address. See Using it without an account for the full detail.

You land on Home. Its Finish setting up card lists only what still needs attention, such as the Microsoft connection, a tenant without GDAP delegation or the Exchange module, and links each item to the screen that fixes it.

4. Connect Microsoft

To act in customer tenants, the bridge uses the same CSP setup most MSPs already have. It reaches each tenant through your GDAP relationship and a multi-tenant app under the Secure Application Model. Nothing is installed in the customer tenant.

RequirementWhy
A multi-tenant Entra app registration in your partner tenant (client id + secret in the Partner config section) This is the Secure Application Model app that acts on your behalf.
GDAP relationship per customer, with roles covering what you use (Intune administration, user management, Exchange recipient management) Scopes what the bridge can touch in each tenant. No GDAP, no access: the tenant shows as NoDelegation.
Per-customer admin consent for the app Standard multi-tenant app consent in each customer tenant.
A one-time SAM bootstrap by an MFA'd admin agent Seeds the encrypted, auto-rotating refresh token the bridge exchanges for per-tenant Graph tokens.
(Exchange workflows only) an app-only certificate for Exchange Online PowerShell (Exchange config section) Mailbox configuration is not fully exposed by Graph; the bridge shells out to the EXO V3 module with certificate auth.

Tell the bridge about your app registration

The Windows build reads optional settings from pcb.local.json in its data folder. Create %LOCALAPPDATA%\PartnerCenterBridge\pcb.local.json with your app's details, then restart the program: 

{
  "Partner": {
    "ClientId": "<application (client) id of the multi-tenant app>",
    "ClientSecret": "<client secret>",
    "PartnerTenantId": "<your partner tenant id>"
  }
}

This file is plain JSON in your per-user data folder, which the program restricts to your Windows account where it can. If you would rather not keep the secret in a file, set it as an environment variable (Partner__ClientSecret) or pass it on the command line (--Partner:ClientSecret=...). Both take precedence over pcb.local.json.

Run the one-time SAM bootstrap

.\PartnerCenterBridge.exe bootstrap-sam

It prints a sign-in URL and code. Sign in with an MFA'd admin-agent account from your partner tenant. The bridge stores the refresh token encrypted in its data folder and rotates it on every use. The command exits when it is done and does not start the web app. Other ways to seed the token are described in SAM bootstrap.

App registration permissions

The Secure Application Model uses delegated (App+User) permissions: the bridge acts as the admin agent whose refresh token you seed at bootstrap. Grant these delegated permissions on the multi-tenant app registration and admin-consent them in your partner tenant. Effective access in each customer tenant is the intersection of this list with the roles on that customer's GDAP relationship.

APIDelegated permissionUsed for
Partner Center (https://api.partnercenter.microsoft.com) user_impersonation Customer list sync; the SAM token exchange itself.
Microsoft Graph DeviceManagementApps.ReadWrite.All Win32 app templates: create, upload and assign Intune apps.
Microsoft Graph User.ReadWrite.All New hire, offboard (block sign-in, revoke sessions), license assignment, user lookups.
Microsoft Graph Group.ReadWrite.All Adding/removing group membership during provisioning and offboarding.
Microsoft Graph UserAuthenticationMethod.ReadWrite.All MFA reset and compromised-account lockdown (enumerating and deleting auth methods).
Microsoft Graph User-PasswordProfile.ReadWrite.All Password reset workflow.
Microsoft Graph Organization.Read.All Reading subscribed SKUs for the license pickers and license repair.
Microsoft Graph Policy.Read.All Config snapshots: reading Conditional Access Policies and Named Locations.
Microsoft Graph DeviceManagementConfiguration.Read.All Config snapshots: reading Device Compliance Policies.
Treat this as the minimum. Because tokens are requested with /.default, the bridge can only ever use what is consented on the app. Adding a permission later means re-consenting in the partner tenant (customer tenants inherit via GDAP + the multi-tenant consent).

5. Add your customer tenants

Open Tenants and choose Sync from Partner Center to pull in your customer list, or add a tenant by hand. Adding tenants is an Administrator task, and the Administrator who adds a tenant becomes its Owner. Each tenant shows its delegation status, so a customer without a GDAP relationship is flagged NoDelegation instead of failing later.

To give colleagues access on the same instance, share a tenant with them as Viewer, Operator or Owner. Even an instance Administrator cannot bypass these per-tenant grants.

Optional: Exchange Online

Mailbox operations (mailbox archive repair, and converting or forwarding a leaver's mailbox during offboarding) run through Exchange Online PowerShell, out of process. They need three things, and the app says which one is missing instead of failing silently. In the Windows Local Workbench, an instance Administrator can install the first two from the Home setup checklist or Settings after confirming; the commands below remain available for manual setup:

  1. PowerShell 7 (pwsh) on PATH, or its path in Exchange:PwshPath.
  2. The ExchangeOnlineManagement module installed for it: 
    pwsh -c "Install-Module ExchangeOnlineManagement -Scope CurrentUser"
  3. An app-only certificate: set Exchange:AppId in pcb.local.json, then either import the certificate into Cert:\CurrentUser\My and set Exchange:CertificateThumbprint (preferred on Windows -- no certificate secret is handled by the app), or place the PFX at certs\exo.pfx in the data folder and set Exchange:CertificatePath (plus Exchange:CertificatePassword if it's protected; that password reaches pwsh only over standard input, never a temporary file). The app needs Exchange.ManageAsApp and the Exchange Administrator role.

Run .\PartnerCenterBridge.exe doctor afterwards. The pwsh, exchange-module and exchange-app checks should all pass. Full detail: Exchange Online as an optional dependency.

The Exchange organization is read from Microsoft Graph for that tenant (its verified initial *.onmicrosoft.com domain, checked against the tenant's own Entra id) the first time an Exchange operation runs, so the Graph connection has to work for that tenant too. If the connection ever answers for a different organization, the operation is refused and nothing is changed.

Your first session

  1. Find a person. Search from Home or People across every active tenant and open their workspace: summary, access, licensing, authentication, mailbox, devices and history.
  2. Run a known fix. MFA reset, password reset, compromised-account lockdown, license repair or mailbox archive repair. Each one shows its diagnosis before anything changes. See Workflows.
  3. Mirror access or offboard someone. Review the plan, apply what you choose, and copy the ticket notes from the evidence view. See Operations.
  4. Set up a contract. Group tenants into a contract, add an app template (an .intunewin from the Microsoft Win32 Content Prep Tool) or provisioning defaults (licenses, groups, UPN domain), and deploy.
  5. Take a config snapshot (optional). Back up Conditional Access, Named Locations and Device Compliance policies for a tenant and diff any two captures. See Config snapshots.

Prefer Docker or a shared server?

The same app also runs as containers (Postgres, the API and the web app) for teams that want one shared instance, with sign-in through your own OIDC provider or local accounts. Docker Compose with the published ghcr.io images is the quickest way to evaluate it, and the repository includes a Kustomize template for Kubernetes. See Run as a server.
